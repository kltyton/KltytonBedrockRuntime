Kltyton Bedrock Runtime 开发示例操作说明

一、用途
本目录只用于开发环境手动检查动画图、GeckoLib 替换渲染、poly_mesh 和树/烘焙模型模式。
发布 JAR 不包含 examples 类、资源或示例 mod 元数据；单独安装 Kltyton Bedrock Runtime 不会注册这些示例。

二、启用方式
仅在目标工程中加 -Pdevelopment_examples，示例会被编入同一次正常 build。
示例源码集通过真实 Loom / NeoForge / legacyForge mods sourceSet API 注册为独立开发 mod：
  kltyton_bedrock_runtime_examples

NeoForge 26.2 示例：
  cd targets/neoforge-26.2
  .\gradlew.bat build -Pdevelopment_examples
  .\gradlew.bat runClient -Pdevelopment_examples

Fabric 26.2 示例：
  cd targets/fabric-26.2
  .\gradlew.bat build -Pdevelopment_examples
  .\gradlew.bat runClient -Pdevelopment_examples

26.1.2 目标使用相同参数。
1.20.1 与 1.21.1 在对应 targets 目录同样执行 build / runClient 并加 -Pdevelopment_examples。
1.20.1 与 1.21.1 使用 GeckoLib 4 适配层：
  - 1.20.1 使用 software.bernie.geckolib.core.* 包以及 GeoReplacedEntityRenderer。
  - 1.21.1 使用 software.bernie.geckolib.animatable/animation.* 包以及同一替换渲染器。
  - 图动画由库的 GeoModel.handleAnimations RETURN Mixin 应用，本示例不额外添加
    GraphAnimationLayer，也不改变标准 GeckoLib 渲染层和原生事件语义。

三、进入世界后的场景
示例只在客户端替换以下原版实体的渲染，不改原版 AI、攻击、交互或存档逻辑。
用原版命令生成实体即可：

  /summon minecraft:pig
  /summon minecraft:armor_stand
  /summon minecraft:cow
  /summon minecraft:sheep
  /summon minecraft:chicken
  /summon minecraft:zombie
  /summon minecraft:skeleton
  /summon minecraft:husk

1. Pig：一维速度混合（idle / walk / run）
   手动操作：玩家静止、步行、疾跑。观察 Pig 的 idle、walk、run 三个片段按玩家速度连续混合。

2. ArmorStand：二维方向/瞄准混合
   手动操作：玩家旋转视角、上下看。玩家头部水平偏航和俯仰分别驱动 ArmorStand 的二维混合。

3. Cow：腿部移动 + 上半身瞄准权重
   手动操作：玩家一边移动一边看向不同方向；玩家潜行会降低 Cow 上半身瞄准权重。
   观察下半身继续播放 walk，上半身/头/手臂来自 mask 后的 aim 姿态。

4. Sheep：原版 additive 控制器协作
   手动操作：玩家移动或静止，玩家潜行改变 Sheep 的图 additive 权重。
   主控制器播放 idle；GL5 下独立的原版 additive 控制器播放 breath；图本身再叠加 wave。
   GL5 可同时检查原生 additive 与 GraphAnimationLayer 的叠加顺序。
   GL4 4.x 没有 GL5 的 additive 控制器标记，因此 GL4 只演示图 additive，不伪造原生 additive。

5. Chicken：Hermite 过渡
   自动循环：每 60 tick 改变 phase，在 idle 与 attack 之间做 Hermite 过渡。
   手动操作：观察过渡是否平滑、是否有跳变或骨骼残留。

6. Zombie：cubes + poly_mesh
   观察普通 cube 和 poly_mesh 披风同时渲染；披风每 2 秒旋转一次。
   该模型同时包含 tree 模式元数据，供网格/捕获路径读取。

7. Skeleton 与 Husk：Tree / Baked 对照
   Skeleton 使用 example_tree.geo.json（kltyton_bedrock_runtime.model_mode=tree）。
   Husk 使用 example_baked.geo.json（kltyton_bedrock_runtime.model_mode=baked）。
   两者几何、动画、贴图相同，只比较模型模式处理结果是否一致。

四、图参数来源
示例不添加自定义网络包或 UI。视觉图参数来自本地玩家，而非被替换实体自身的 AI 状态：
- 一维速度：本地玩家水平移动速度；玩家步行/疾跑驱动 Pig 的 idle/walk/run 混合。
- 二维瞄准：本地玩家头部相对身体的水平偏航与俯仰；玩家转头/上下看驱动 ArmorStand。
- 腿部/上半身：本地玩家潜行状态改变上半身瞄准权重；玩家移动与潜行驱动 Cow。
- additive：本地玩家潜行状态改变图 additive 权重；玩家移动/潜行驱动 Sheep。
- Hermite：本地玩家 tickCount 的 60 tick 循环相位。
- 无本地玩家（真实菜单/加载边界）时清除图参数，回到图默认值；不会伪造恒定玩家输入。
- 被替换实体仍保留自己的动画控制器、动画时钟和实例 ID；只有图参数读取本地玩家。

Zombie 的 poly_mesh 视觉场景使用资源内联图，而不是 ExampleScene 里的 Java 图：
  - 26.x：assets/kltyton_bedrock_runtime_examples/geckolib/models/entity/kltyton_bedrock_runtime/example_humanoid.geo.json
  - 1.20.1 / 1.21.1：assets/kltyton_bedrock_runtime_examples/geo/entity/kltyton_bedrock_runtime/example_humanoid.geo.json
编辑文件内 kltyton_bedrock_runtime.graph 的 nodes/output 后保存。开发客户端实际读取的是目标工程
build/resources/developmentExamples 下的资源输出；将改动同步到该输出，或由开发者主动
执行 processDevelopmentExamplesResources 后，在游戏中按一次 F3+T 触发资源重载。
权威资源继续保存在 examples/src；F3+T 本身不会替代 Gradle 的资源复制任务。
重载后当前 baked model 与新 graph 一起替换；每个实体实例的 GraphRuntime 会因新定义而失效
并重建。资源图不会自动推进时间轴，也不会自动派发时间/事件回调；时间仍由现有动画采样路径提供。
其他六个视觉场景继续使用 Java API 图。

五、参数捕获计数
ExampleTelemetry 统计参数捕获的调用频率：
  - GraphAnimatable.captureGraphParameters 回调调用次数；
  - 每个场景的这些回调次数。
日志格式：
  Development example graph captures <回调总数> (<场景=回调次数> ...)
渲染调用、CPU、分配和帧时间数据由对应渲染计数器或性能分析工具采集，方法见下一节。

六、手动性能采集（不自动运行）
示例不会在 runClient 时自动启动任何 profiling。需要时手动执行以下步骤。
在可用的 PowerShell 7 / pwsh 中，请选择你自己的输出目录：
  $out = '<你的输出目录>'
  New-Item -ItemType Directory -Force -Path $out | Out-Null
  $jcmd = (Get-Command jcmd.exe).Source
  Get-Process javaw | Select-Object Id, ProcessName

  # 用实际 PID 替换 <PID>；profile 设置包含 CPU 采样和分配采样
  & $jcmd <PID> JFR.start name=bhl-examples settings=profile duration=120s filename="$out\examples.jfr"

  # 或者手动停止：
  & $jcmd <PID> JFR.stop name=bhl-examples filename="$out\examples.jfr"

查看：
  & (Join-Path (Split-Path $jcmd) 'jfr.exe') summary "$out\examples.jfr"
  # 或用 JDK Mission Control / jfr print 打开 "$out\examples.jfr"

CPU 与分配的分工：
  - JFR settings=profile 的 jdk.ExecutionSample 用于 CPU 采样分布。
  - JFR settings=profile 的 jdk.ObjectAllocationSample 用于分配采样分布。
  - JFR 不直接给出 frametime 分布；帧时间需手动使用 Minecraft F3 帧时间图或独立外部采集。
    本示例不提供伪造数值，也不会自动运行这些工具。

采集注意事项：
  - 先进入世界并稳定到目标场景，再开始 JFR。
  - 固定实体类型、数量、视角、移动方式后再比较样本。
  - 不要把不同机器、不同视距或不同实体数量的结果混在一起。

七、ArmorStand 开发命中箱（额外场景，不是第 8 个视觉场景）
只有带 kltyton_bedrock_runtime_demo 标签的 ArmorStand 才注册可视 OBB；未标记的普通 ArmorStand
使用 reject-all 选择器，不匹配任何骨骼、不启用物理碰撞，保持原版行为。该场景仅用于开发
验证选择/命中/交互/软碰撞，不改 AI，不新增伤害或实体/物品/UI。

生成时直接带标签，避免先渲染后被缓存成未标记状态：
  /summon minecraft:armor_stand ~ ~ ~ {Tags:["kltyton_bedrock_runtime_demo"]}

标签 NBT 键为大写开头的 Tags；已按 1.20.1、1.21.1、26.1.2、26.2 的 Entity 保存/加载
键核对，四个版本使用同一条命令，不需要版本分支。

标记后：
  - ALL 可视 cube 注册为 OBB；
  - HURT 与 SOFT COLLISION 已注册；
  - 交互使用 BoneHitboxEntity 的标准 OBB 交互回调，默认仍为 PASS。
不要对已经生成的普通 ArmorStand 追加标签；未标记状态首次创建后不会重建，请重新生成
带 Tags 的新 ArmorStand。本示例不提供伪造的运行时刷新。

八、限制
- 示例不拦截攻击/交互事件；原版控制仍按原逻辑执行一次。
- 示例替换的是客户端渲染器，服务端仍是原版实体。
- 示例资源全部为本仓库自制的最小几何、动画和程序生成贴图，不包含第三方示例资产。
- 示例 mixin 和 kltyton_bedrock_runtime_examples 元数据只存在于开发示例源码集，不进入正式发布 JAR；
  未启用 -Pdevelopment_examples 时不会加载。
- GL5（26.1.2 / 26.2）和 GL4（1.20.1 / 1.21.1）示例路径均已接入；GL4 图应用依赖
   库的 GeoModel.handleAnimations RETURN Mixin，不使用 GraphAnimationLayer。
- 示例通过 EnhancedModels.registerResource / bindEntity 在客户端与服务端注册相同模型资源，
  用于精确服务端网格查询；视觉图仍只在客户端渲染器上显示。
